## 〇、总体判断（先给结论）

该章的技术底座扎实：NNPot 模块、gmxapi 设计目标、GPU/并行机制等主干描述经独立核验与真实发布线一致（见附录 A），引用纪律也优于同类中文参考书。但作为一本**面向同行**的「Python 生态与扩展开发」参考章，其价值密度分配失衡：

1. 约四成篇幅（11.1 数值回顾 + 11.2 并行架构，约 90 行）是对手册与第 5/6 章内容的压缩复述，对同行信息增量低；
2. 同行最需要的三块——**gmxapi 插件的实操闭环**、**自定义分析工具的完整实现走查**、**机器学习势的验证与不确定性**——恰恰停留在「能跑/能用」的描述层（11.6.3 仅 3 行、11.4 没有一个可运行的实现示例）；
3. 被移除的七道习题中至少两题（并行配比决策、NNP 可行性论证）具有纯正文无法替代的**方法论价值**，建议回填为案例解剖与方法学评注，而非一律删除；
4. v1 遗留的 P2 项（gmxapi 版本表述不一、lincs-order 因果断句）在现行稿中仍未结清。

语言与引用层面接近可出版；方法学纵深与同行价值层面，需要一轮以「决策指南 vs 工具罗列」为目标的定向修订。

## 一、depthGaps（关键主题是否只停在"能跑/能用"）

> 编号 D1–D9，均给出小节、行号与所缺。

### D1 11.1.1（L53–55）：时间步长只给经验值，缺定量稳定性判据与大步长策略
- 现行：`dt` 上限用「最快运动周期一半」「经验取值 2 fs/1 fs/10–20 fs」表述，并把「辛性质」一句带过。
- 所缺：(a) Verlet/leap-frog 的线性稳定性界限（ω·Δt < 2 量级）——这是同行判断「为什么氢键被约束后能到 2 fs」的数学依据，书中「周期一半」是教学式背书的简化；(b) **HMR（氢质量再分配，4–5 fs）**完全缺席——这是现代蛋白体系实际上限 dt 的标准工程手段，且伴生伪影（粘度/扩散系数系统偏移、控温耦合）属于同行必须知道的边界；(c)「取值过小则浪费算力而不改变平衡态结果」缺乏「在已收敛区间内」的限定（见 P1）。
- 建议：补 2–3 句稳定性判据 + HMR 一段（候选文献已核：Hopkins C W, et al. J Chem Theory Comput, 2015, 11(4): 1864-1874. DOI: 10.1021/ct5010406，作者仍需按 STYLE 六项核验后入 refs）。

### D2 11.1.2（L61、L63）：LINCS 边界与收敛判据表述粗糙，且未结清 v1 P2-4
- L61「若用距离约束把多个角耦合起来形成高连通**环**结构，特征值会接近或超过 1」——LINCS 展开不收敛的典型情形是**四面体中心（如 sp³ 碳）多个角约束共享同一键的耦合**，不是「环」；「高连通环」是教学式类比且不准确。
- L63「lincs-order 是矩阵展开阶数，MD 计算用四阶**即可达到**每约束相对偏差小于 0.0001」——v1 P2-4 已指出这是把手册两句（「MD 用四阶展开」「单步修正后相对偏差 <0.0001」）误接为因果，现行稿仍未断句。
- 所缺：谱半径 <1 的成立条件一句、`lincs-iter` 与 `lincs-warnangle` 的相互作用、「频繁警告」的量化判据（如警告帧占比>1% 即应减步长）。

### D3 11.1.3（L67–69）：PME 缺误差权衡的量级关系
- 现行正确给出 fourierspacing/pme-order/ewald-rtol/rcoulomb 的缩放律（同比例缩放精度近似不变），但只给一个「能量相对精度约 5×10⁻³」的单一落点。
- 所缺：**能量误差与力误差的分离**（二者对网格/截断的依赖不同）、rcoulomb 与 ewald-rtol 的自洽约束、以及「网格间距 ≈ rcoulomb/4 量级」的工程依据。同行调参时最需要的正是这一权衡关系，候选文献已核：Deserno M, Holm C. J Chem Phys, 1998, 109(18): 7678-7693（How to mesh up Ewald sums. I）。

### D4 11.2（L94–119）：并行机制准确，但无「决策实例」
- 11.2.2/11.2.4 全是机制与阈值（3:1/2:1、25–33%、2%、0.8、16 倍），但没有一个从「体系规模→节点/GPU 数→配比→预期瓶颈」走下来的实例。与第 2 章 2.6 节的操作性互为表里，但同行在此处期待的是「如何用这些数字做决策」。
- GPU 卸载（11.2.3）只讲了单 GPU 卸载层，未提**多 GPU 域分解与 PME-on-GPU 的秩平衡**（-npme 与 GPU PME 的关系），也未提任务重叠对插件/自研代码步进延时的量化影响（L113 仅一句且无版本引用锚点）。

### D5 11.3（L129、L141–157、L187）：gmxapi 的实操盲点
- 安装表述含糊：「随 GROMACS 安装…建议在独立虚拟环境中安装」（L129）——未给可执行路径。已核：真实用法页为 `pip install gmxapi` 源码构建 wheel，前提是 GROMACS 以 **GMXAPI=ON 且 BUILD_SHARED_LIBS=ON** 构建、mpi4py 与 GROMACS 同一 MPI 工具链（anysearch 核验）。
- 系综**只展示了如何启动**（L143–147），未展示如何**取回每个副本的输出**（每个副本的轨迹/日志路径导航），而这是系综脚本最常卡住的 API 点；@function_wrapper（L157）一笔带过，无最小子图/循环示例。
- **插件 C++ 侧整体 defer 到文档**（L191）——而「gmxapi 三大支柱之一」的插件力正是本章读者最可能的扩展需求（自定义约束系综、BRER 同族）。至少应给 sample_restraint 参考实现的模块形态（MDModule、注册与构建方式）与 20 行以内骨架。

### D6 11.4（L193–228）：无一个可运行的模板实现走查
- 全文只有 CMake 片段（L216–222）与四个回调名，「分析工具开发」没有**实际代码**。同行读者无法据此写出第一个工具：回调各自签名、`gmx::AnalysisData`/`AnalysisDataHandle` 对象模型、`setFrameCount`、输出聚合路径均未出现。
- 缺数值细节：(a) 自定义工具读 xtc 与读 trr 的**压缩精度差异**对输出误差的影响（第 7 章讲过文件格式，此处应落到"我的工具该读哪个"）；(b) 工具内 PBC/单位约定（L228 有单位列表但无体系化审计）；(c) 框架内线程并行（工具多线程化）——只字未提。
- CMake 示例 `find_package(GROMACS)`（L218）与官方包名大小写（`Gromacs::libgromacs` 靶标已核，config 文件为 `gromacs-config.cmake`）不一致，宜按官方模板给出可复制写法。

### D7 11.5.3（L263–288）：MSM 方法论缺文献锚点与实操判据
- 四步工作流正确，但「隐含时间尺度平台期与 CK 检验必做」（L288）**无一条方法学文献支撑**（现引全是工具论文/文档）；同行会期待 Chodera/Swope/Pitera→Prinz 2011→Husic & Pande 2018 这条锚线。候选文献已核：Husic B E, Pande V S. J Am Chem Soc, 2018, 140(7): 2386-2396. DOI: 10.1021/jacs.7b12191。
- 缺实操判据：lag time 的**单位换算**（帧数 × 输出步长 = 物理时间）、滞后时间平台期判定的主观性、状态离散化（k 值/簇算法）对结果的敏感性、以及 tICA vs VAMP 排序的选择依据——正是同行构建 MSM 时最先遇到的问题。
- PyEMMA 2.5.x（L269）被当作现役工具介绍，但真实发布线其末版为 2023-09 且仓库明示不再积极维护（v1 验收已记录此发现，anysearch 复核 Releases 页一致）——同行选型必须知道。

### D8 11.6（L326、L348–354）：ML 势的深度缺口最重
- **描述符表述不严谨**（L326）：「最常见的描述符是原子位置与原子序数」——原文 NNPot 接口的模型输入确为位置等原始量，但同行语境下"描述符"指**必须内建平移/旋转/置换不变性**的局部环境特征；把原始坐标称为"描述符"会把该方法学关键点（不变性由模型架构承担）掩盖掉。需一句澄清 + 指针。
- **无不确定性量化**：NN 势在训练域外的灾难性外推是上 NNP 时风险最不可控的环节（被删习题 Q7 正是问这个），现行 11.6.3 只给「以未参与训练的量子化学构型…交叉验证」一句，无 UQ 手段（系综分歧/预测区间）、无验证数值协议（测试集能量/力 RMSE 阈、与实验量对照的容差）。
- 成本只给定性「显著更高」，无量级；ML/MM 收益（11.6.4 的 link atom 机械嵌入）缺一个典型省算力比例的锚点。
- 与经典力场的对照缺一个可执行判据（什么条件下 NNP 值得上、什么条件下经典力场+UQ 更稳）。

### D9 11.7（L360–380）：工程化缺"参考数据"与容器化
- 测试策略（11.7.1）好，但缺 **golden-file/已知参考数据**思想：用文献发表的小体系精确量（或内置工具输出）做测试 oracle 是数值软件测试的标准做法，应显式化。
- 11.7.2 明言「只剖析 Python 分析管线」（L376），但 11.4 的 C++ 工具剖析（perf/gprof）与此处无衔接。
- 11.7.3 打包段完全没提容器化/conda-lock——对依赖 GROMACS 构建信息（编译器/MPI 变体，见 L380 自述）的环境，Apptainer/容器是可复现性的第一手段，至少应有一句。

## 三、pedagogyResidue（面向学生的表述残留与教学式简化）

- **L55**：「四问如下。它定义…它必须…同时…」——「四问」是 STYLE 参数框架的内部术语，直接抛出却不分行展开，是排比式教学腔的残骸；「取值过小则浪费算力而不改变平衡态结果」是过度简化（离散化偏置仅在已收敛步长区间可忽略，非严格"不改变"）。
- **L61**：「高连通**环**结构」——见 D2，教学类比且技术不准确（应改为"共享同一键/中心原子的耦合角约束"）。
- **L63**：「用四阶**即可达到**…相对偏差小于 0.0001」——因果误接，v1 P2-4 未结清。
- **L208**：「开发者只需替换核心计算逻辑」——过度包办式表述；参考书口吻应改为「模板固定编译配置与框架接线，开发者保留对核心计算的完全控制」。
- **L247 / L261 / L288**：MDAnalysis、MDTraj、MSM 三节结尾或用同构句式重复「与内置工具交叉验证」，教学式点题三连；应压缩为一处「数值审计原则」（单位/PBC/选择语义），后续引用之（同时是 E5 的落点）。
- **L119**：「避免引入全局归约或阻塞式同步」——建议本身好，但"全局归约"对中文读者无定义，加括号（如 MPI_Allreduce）即转为同行语言。
- **L228**：「grompp 的 -debug 选项…（官方在线帮助文本所述，文档推定）」——文档推定标记合规，但该句靠 grompp.debug 文件调试的说法对自定义工具基本无效（工具不经 grompp 运行），语义上应归入"输入检查"而非"工具调试"，属思路未理清。
