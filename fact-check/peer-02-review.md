### D2｜2.1.3 资源估算：仍只给框架不给量级先验与回退语义（L76–80）

- **现状**：三步法（L78）正确但 L80 立即自限「内存与显存的估算无法由单一公式给出」，此后无任何量级经验值，同行读后对「100 万原子要多少显存/内存」仍无先验；L80「超出显存时 GPU 卸载会自动回退或无法启用[2]」的**回退粒度与日志可见性**问题仍未澄清（02-review P2-4 已提出，正文未改）。

### D3｜2.6.2 编译选项：官方对 GMX_BUILD_OWN_FFTW 的限制与正文推荐直接冲突（L314、L328、表 2-4 L334）

- **已核验 [23]**：官方 build-system 文档明确——`GMX_BUILD_OWN_FFTW`「ninja 构建系统下**不支持**；交叉编译或使用工具链文件的复杂场景**不建议依赖此特性**，应手动构建 FFTW」；且该选项在 configure 期**自动下载** FFTW 源码。
- **冲突点**：正文 L314 将 `-DGMX_BUILD_OWN_FFTW=ON` 作为默认推荐路径；L328 恰在集群交叉编译语境（登录节点配置 + `-DGMX_SIMD` 显式指定）；表 2-4（L334）无任何使用限制。真实集群上两个直接后果：登录节点无外网 → cmake 阶段下载 FFTW 失败；交叉编译/工具链文件场景官方明示不建议。
- **建议**：表 2-4 L334 行补「需构建机可联网；ninja 与交叉编译/工具链场景不适用（官方不建议），改手动编译 FFTW 或系统 FFTW + `GMX_FFT_LIBRARY=fftw`」；2.6.2 补离线路径判据与一句官方限制原文。
- **D3b（已核验 [23]，替代 v1 D5 的静态构建建议）**：v1 建议的 `-DBUILD_SHARED_LIBS=OFF` 不是 GROMACS 官方主开关。官方选项为 **`GMX_BUILD_SHARED_EXE`**（「关闭即尝试构建静态可执行文件，默认 ON」）与 **`GMX_PREFER_STATIC_LIBS`**（默认 OFF，除非前者被关闭）。表 2-4 无静态/自包含构建行——对「整体拷贝部署、与容器互为补充」的同行诉求，应补一行（并指向官方 relocatable-binaries 开发文档）。

### D4｜2.7.2 安装自检：「make check 强信号」的边界未讲清（L421–431）

- **已核验 [23]**：单元测试默认随 `BUILD_TESTING=ON → GMX_BUILD_UNITTESTS=ON` 构建；官方回归测试包默认**不进入**构建（`REGRESSIONTEST_DOWNLOAD` 默认 OFF，为 ON 时 configure 期下载、下载后自动复位 OFF）；`check` 目标语义为「构建测试所需二进制并运行全部测试，某类测试不可用时打印提示」。
- **落在正文的问题**：L423「make check……运行单元测试与基础回归测试」除非读者已自行开启回归测试包，否则默认构建只有单元测试，「安装正确性的**强信号**」（L423）表述过头；L427「可能耗时较久」对不带回归测试包的默认构建也过头；L430 提到测试环境与构建环境「SIMD 档位、驱动版本」不一致，但**未提 GPU 条件**——含 GPU 卸载的测试在无 GPU 的登录/编译节点会被跳过或失败。
- **建议**：把 L423「强信号」限幅为「单元测试为默认；完整回归测试包需 `-DREGRESSIONTEST_DOWNLOAD=ON` 并在 configure 期联网下载」；L430 补「含 GPU 的测试应在与计算节点同类型（有 GPU、同驱动）的环境中执行，或按 known issues 与测试名确认可跳过」；另 L431「物理校验（physical validation）[29]」引文定位偏差（[29] testutils 页未含该内容，02-review P2-10）仍未修，应改引 Regression tests 文档或删句。

### D7｜常见错误 #3 的处置句与 GROMACS 单二进制设计不符（L493）

- **原文**：「处置：在集群上使用 `-DGMX_SIMD=` 显式指定计算节点的档位……并**分别编译分析工具（可用低档位）与 mdrun（用最优档位）**。」
